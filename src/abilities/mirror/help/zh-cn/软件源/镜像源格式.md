# 镜像源格式

> 最后更新：2026-10-01

「软件源」页面的所有读取和写入都围绕一个文件：`/etc/pacman.d/mirrorlist`。它在 pacman 眼里是
普通的 mirrorlist，在 Cockpit 眼里则靠一套 `[MIRROR]` 注释格式认识「哪个源叫什么名字、是开是关」。

## [MIRROR] 格式

每个源由两行组成：一行 `# [MIRROR] <名字>` 注释头，紧跟一行 `Server = ...`。
**禁用就是把 `Server` 行注释掉**（`# Server = ...`），启用就是去掉注释：

```
# [MIRROR] USTC
Server = https://mirrors.ustc.edu.cn/archlinux/$repo/os/$arch

# [MIRROR] TUNA
# Server = https://mirrors.tuna.tsinghua.edu.cn/archlinux/$repo/os/$arch
```

上面这份例子里，USTC 启用、TUNA 禁用。规则：

- `Server = ` 开头 = **启用**；`# Server = ` 开头 = **禁用**。
- 名字只活在注释头里，随便起；页面按名字展示和开关。
- URL 里的 `$repo` / `$arch` 是 pacman 的占位符，原样保留，别替换掉。
- 注释头与 Server 行之间允许空行；文件里其余的注释、空行、说明文字一律原样保留。

## 旧格式与迁移

pacman 传统的 mirrorlist 是裸的 `Server = ...` / `# Server = ...` 行，没有名字。
这种情况页面也能直接读：源名从 URL 猜（比如 `mirrors.ustc.edu.cn` → `USTC`），照样列出来、
照样能开关。

只是从第一次开关起，Cockpit 一律按 `[MIRROR]` 格式写回——具体来说是把
`# [MIRROR] <名字>` + `Server = <URL>` 这个块**追加到文件末尾**，原有的其它行一个字不动。
所以旧格式文件第一次操作后，文件里可能同时留着旧裸行和新块（同一个 URL 出现两次，pacman 会访问
两遍）。建议操作一次之后，顺手把旧的裸行清掉，只留 `[MIRROR]` 块。

## 写入的安全保证

每次开关都是一次完整的「读 → 改 → 原子替换」：

1. **读取**：操作前重新读一遍文件（以磁盘为准），所有操作串行排队，快速连点不会互相覆盖。
2. **只改一行**：除了目标源的 `Server` 行加 / 去 `# ` 前缀，其它行原样保留。
3. **临时文件 + mv**：新内容写到 `/tmp` 下的临时文件，再由 pkexec 调用的 helper 脚本
   （`scripts/write-mirrorlist.sh`）先备份原文件为 `/etc/pacman.d/mirrorlist.cockpit.bak`，
   然后 `mv -f` 原子替换。同分区下 `mv` 是原子操作：要么成功，要么原文件完全不受影响。
4. **提权失败即中止**：密码框取消 / 输错、脚本执行失败，都在替换之前返回错误，原文件不动，
   页面顶部显示 `pkexec 失败: ...`。
5. **找不到目标不硬写**：要开关的源在文件和预置配置里都不存在时，直接提示
   `未找到镜像源: <名字>`，不写文件。

## 预置一批源（可选）

`~/.config/LinuxCockpit/mirror/config.json` 可以预先放一批源：

```jsonc
{
  "mirrors": [
    { "name": "USTC", "url": "https://mirrors.ustc.edu.cn/archlinux/$repo/os/$arch" },
    { "name": "TUNA", "url": "https://mirrors.tuna.tsinghua.edu.cn/archlinux/$repo/os/$arch" }
  ]
}
```

页面上它们会与 mirrorlist 的内容合并显示：URL 已存在的不重复添加，没出现的以**已禁用**状态
追加进来，拨下开关即按上面的流程写入 mirrorlist（文件里没有对应 `[MIRROR]` 块时会自动追加）。
