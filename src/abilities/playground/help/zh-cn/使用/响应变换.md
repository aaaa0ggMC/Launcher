# 响应变换

> 最后更新：2026-10-01

「响应变换」挂在模板上，用来把原始响应里有用的部分抽出来：正文截取、图片、音频、视频，
或者对接「先返回任务 ID、再轮询结果」的异步接口。变换结果汇总在 **最终响应** 区，
原始响应仍然完整保留在下面的 **响应** 区。

## 变换链怎么管理

在模板编辑的「响应变换」区：

- **添加变换** 在链尾追加一条，新变换默认类型是 `text`（名称留空时显示 `#1`、`#2`…）。
- 每条变换的标题行可点击折叠 / 展开；行右侧三个图标按钮依次是 **上移**、**下移**、**删除**。
  变换按列表顺序执行，顺序会影响结果在「最终响应」里的排列。
- 「类型」下拉可选：`Text`、`Image`、`Audio`、`Audio URL`、`Video URL`、`Task`、`Script`。
- 原始响应、变换配置或全局变量一变，同步型变换（text / image / audio / script）会自动重算；
  `Audio URL` 与 `Video URL` 每次都会重新下载。没有配置任何变换时该区显示「暂无变换」。

## 七种变换分别怎么填

| 类型        | 要填的关键字段              | 得到什么                                              |
| ----------- | --------------------------- | ----------------------------------------------------- |
| `text`      | 格式（`{.path}`）           | 一段文本，长文本折叠显示                              |
| `img`       | 入口路径                    | 直接显示图片，每张图带 **下载** 按钮                  |
| `audio`     | 入口路径、编码              | 可播放的音频播放器（原始 base64 解码而来）            |
| `audio-url` | 入口 URL、MIME 类型（可空） | 音频播放器；多个地址会拆成子条目，每个都能播放 / 下载 |
| `video-url` | 入口 URL、MIME 类型（可空） | 视频播放器；多个地址同样拆成子条目                    |
| `task`      | 任务 ID 路径、轮询 URL 等   | 后台轮询异步任务，结果（含子变换）回到「最终响应」    |
| `script`    | 脚本（JS）、局部变量        | 由脚本自行决定输出文本、图片、音频还是视频            |

### text：按 JSON 路径拼文本

「格式」框里混合普通文字和 `{.路径}`，例如：

```text
回答：{.choices[0].message.content}
```

- 数组会自动逐项展开，输出枚举成的多行（`0. …`、`1. …`）。
- 多个路径落在同一个数组上时用 `[X]` 绑定同步，例如
  `{.data[X].id} {.data[X].abilities}` 会按同一索引配对输出。
- 不同数组根之间做笛卡尔积，结果行数会相乘，慎用。
- 抽不到值时原样输出 `{.路径}`，方便判断是路径写错还是数据真的没有。

### img / audio：从响应里取内联数据

- `img` 按 **入口路径** 取出所有字符串值当作图片地址，全部渲染出来，每张图下有 **下载**。
- `audio` 按 **入口路径** 取出字符串，按 **编码**（Base64 / Hex8）解码成浏览器可播放的音频；
  **MIME 类型** 留空时按数据头自动识别，识别不了再按 `audio/mpeg` 处理。

### audio-url / video-url：远程媒体

按 **入口 URL** 取出 `http(s)` 地址，逐个下载到内存后播放。填了 **MIME 类型** 就优先用它，
否则按响应头或文件后缀猜测。取到一个就是单个播放器；取到多个时父条目显示「n 个 …」，
下面按序号列出子条目，各自播放、各自下载。下载失败会在结果里给出 `Failed to fetch`。

### script：自己写 JS 处理响应

脚本里可用的对象：

- `object`：解析后的响应 JSON。
- `global_vars`：右侧面板定义的全局变量。
- `context.transform.add_text(label, text)` / `add_img(label, url)` /
  `add_audio(label, src, type)` / `add_video(label, src, type)`：往结果里追加一段输出。
- `context.local.NAME`：读取下面「局部变量」里配置的键值对（以 `context.local.` 访问）。
- `console.log`：输出会进主进程日志，不会显示在页面上。

注意脚本输入框是**草稿**：只改文字不会重新执行，点右侧 **更新** 才提交并运行
（有未提交改动时按钮文字后面会出现 `*`）。脚本抛错时，结果里会多一条 `Script error: …`。

### task：异步轮询

适合「提交任务 → 拿到 task_id → 轮询直到成功」的接口。逐字段说明：

| 字段             | 含义                                                               |
| ---------------- | ------------------------------------------------------------------ |
| 任务 ID 路径     | 从初始响应里取任务 ID 的 JSON 路径，如 `.task_id`                  |
| 轮询 URL         | 轮询地址，支持 `{变量}`、`{.jsonpath}` 与 `{task_id}` 占位         |
| 请求头           | 每行 `Key: value`                                                  |
| 查询参数         | 默认自动补 `task_id=<id>`；自己写了含 task_id 的参数就不会重复追加 |
| 状态路径         | 轮询响应里表示状态的 JSON 路径                                     |
| 成功值           | 状态值等于它才算完成                                               |
| 失败值           | 状态值等于它立即判失败                                             |
| 失败原因路径     | 判失败时从这个路径取原因，显示在结果里                             |
| 轮询间隔 (ms)    | 每次轮询的间隔，默认 2000                                          |
| 响应变换（嵌套） | 完成后再对轮询响应跑一串变换，可再嵌套 task                        |

轮询由后台作业 `pg-task` 执行，所以**切到别的能力甚至关掉页面都不影响**：

- 发送后如果模板里有 task 变换，侧栏「后台任务」会多出一条任务（名称为模板名），
  详情用结构化 response 视图展示，里面有 **停止** 按钮可随时中断。
- 结果通过事件回到页面，「最终响应」区按标签列出；带子条目的结果右侧有刷新图标
  （悬停显示 **重试任务**），点它只重跑这一条 task。
- 进行中、还没有结果时，response 视图显示三点加载动画与「任务轮询中…」。

## 结果长什么样

- **最终响应**：标题行点击可整块折叠。文本超过 400 字符收成几行并加渐隐，
  底部 **展开全部** / **收起** 可切换；图片、音频、视频按各自方式渲染并带 **下载**。
  结果很多时分批加载，滚到底部出现「加载中…」会自动接着显示。
- **响应**：原始响应区。JSON 有 **树** / **原始** 两种看法，非 JSON 只有 **原始** 折叠开关；
  右上角 **复制** 与 **下载**、标题行 **清空**。
- 标签为 `Raw Response` 的结果右侧有下载图标，可把轮询到的原始文本存下来。
