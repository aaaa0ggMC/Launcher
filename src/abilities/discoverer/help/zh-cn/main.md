# 设备发现

> 最后更新：2026-10-11

「设备发现」让同一局域网里的 Launcher 互相发现：每隔几秒往局域网广播一次自我介绍，
同时听别人广播。你不用开终端 `ifconfig`，也能在页面上看到每台机器的名字和 IP——
相当于一个**局域网蓝牙**。

> 一句话上手：设置 → 设备发现 填好**设备显示名** → 回页面点**开始发现** →
> 局域网里其他同样开着发现的 Launcher 会自动出现在列表里。

## 能做什么

- 本机信息卡：设备名、IPv4 / IPv6、平台图标（Linux / Windows / macOS / 安卓）与桌面环境、UDP 端口、广播状态。
- 设备列表：每个被发现的设备一张卡片——名字、平台图标、IPv4 / IPv6、最后见到时间。
- **发送一次**：不等周期，立刻广播一条自我介绍。
- **验证（蓝 V）**：和对方填了相同共享密码时，设备名旁会出现蓝色验证标记。
- 开机自启：在 设置 → 开机服务 里打开后，每次启动 Launcher 自动开始发现（默认关）。

## 界面速览

| 区域       | 位置       | 说明                                              |
| ---------- | ---------- | ------------------------------------------------- |
| 顶部操作栏 | 页面最上方 | 发送一次 / 开始（停止）发现 / 设置齿轮            |
| 我的设备   | 操作栏下方 | 本机名字、平台、IPv4、IPv6、端口、广播状态        |
| 设备列表   | 页面主体   | 每个已发现设备一张卡片，10 秒没再见到的卡片会变淡 |
| 空状态     | 无设备时   | 提示你去启动发现                                  |

卡片上的按钮：未验证且填了共享密码时显示**验证**；已验证的设备显示**取消验证**。

## 常见操作

### 设置设备显示名

点页面右上角齿轮（或 设置 → 设备发现），填写**设备显示名**后保存。这个名字会随广播
发给局域网里的其他 Launcher，是它们在列表里看到的名字。最多 32 个字符。

端口（默认 47820）和广播周期（默认 5 秒）也在同一处修改；**改端口 / 周期后，正在运行
的发现任务要先停止再重新开始才生效**。

### 开始 / 停止发现

- **开始发现**：启动一个后台任务（可在侧栏「后台任务」面板里看到它的日志），之后每
  周期广播一次并持续监听。
- **停止发现**：页面上的停止按钮，或去后台任务面板里停掉「设备发现」任务。
- 想每次开 Launcher 都自动开始：设置 → 开机服务 → 打开「设备发现」。这个服务被标记为
  **退出时直接结束**——关闭 Launcher 时不弹窗、直接终止（发现的只是名字和 IP，不重要）。

### 设置验证（蓝 V）

验证默认关闭。开启方式：在**想要互相信任的两台设备上**填写**相同的共享密码**
（设置 → 设备发现 → 验证）。

- 发现对方后，会自动向局域网二次推送验证报文；密码匹配成功即打上蓝 V。
- 也可以点设备卡片上的**验证**按钮手动触发一次。
- 共享密码加密后存在本机配置里；页面和 `config-get` 都只能看到「是否已设置」。
- 在已认证设备上点**取消验证**（或设置里移除芯片）即可撤销标记。

## 报文长什么样

两种报文都走 UDP 广播（`255.255.255.255:47820`），只在同一广播域内传播
（跨路由器 / VLAN 看不到，这是广播的固有限制）。

**认识报文**（周期性发送）：

```
[16B 随机 AES-128 密钥][4B 名字字节长度][密文]
密文 = AES-128-CTR(密钥, 全零 IV) 加密的：
  名字 UTF-8 || IPv4(4B) || IPv6(16B) || 平台(1B) || 桌面环境(1B)
```

- 密钥每次发送都重新随机，外界看到的就是一段随机字节；
- 名字、IP、平台全部定长变换（流式加密，明密文等长），不用凯撒——
  IPv4 常有大片 `0x00`（如 `10.0.0.1`），凯撒的「每字节 +k」会暴露规律。

**验证报文**（共享密码 AES-256-CTR 加密后广播）：

```
[类型(1B: 请求/应答)][时间戳(8B)][名字长度(2B)][名字][随机填充(0–48B)]
```

- 不需要填「你的设备名」：验证同样走广播，结尾随机长度填充用来混淆报文长度；
- 时间戳只用于防重放（±2 分钟内的才认）；
- 收到能解开的「请求」才会回一条「应答」，不会互相触发形成广播风暴。

## 命令行

```bash
discoverer.config-get                                  # 查看配置（密码只回是否已设置）
discoverer.config-save --deviceName "书房台式机"        # 改设备名
discoverer.self                                        # 本机信息
discoverer.peers                                       # 已发现设备
discoverer.announce                                    # 立即广播一次
discoverer.start                                       # 启动发现任务
discoverer.verify --name "书房台式机"                   # 手动发验证请求
discoverer.unverify --name "书房台式机"                 # 取消验证标记
```

## 常见问题

**页面是空的？** 三种可能：没点开始发现；设备名还没设置；局域网里没有别的 Launcher
在广播（对方也要开着设备发现，且端口一致）。

**看不到某台设备？** UDP 广播不跨路由器 / VLAN。检查两台机器是否在同一广播域
（同一交换机 / 同一 Wi-Fi），防火墙是否放行了对应 UDP 端口。

**IP 显示「未知」？** 对方没有自报 IPv4（比如只有 IPv6 环境），这时显示报文来源地址；
来源也拿不到才显示未知。

**验证总是不成功？** 两边共享密码要完全一致；时间戳窗口是 ±2 分钟，两台机器时钟
差太多也会失败（对一下系统时间）。

**改了什么不生效？** 端口 / 周期改完后，停止再重新开始发现任务。

**关闭 Launcher 时任务会怎样？** 开机自启启动的发现任务标记为「退出时直接结束」，
关闭时不弹窗、直接终止；手动开始的任务会按全局规则弹窗确认。
