# 服务

> 最后更新：2026-10-01

「服务」列出当前用户的 systemd 服务（`systemctl --user`），一行一个：名字、状态、描述都在，
右边直接 **启动 / 停止 / 重启**。适合管理那些以用户服务方式常驻的程序（同步客户端、开发服务器、
自己写的 unit……），不用再开终端敲 systemctl。

> 一句话上手：在搜索框输入服务名 → 在该行右边点红色 **停止** 或绿色 **启动** 图标按钮。

## 能做什么

- 列出全部用户服务（含未激活的，默认只显示 active 的）。
- 按服务名 / 描述搜索，一键刷新。
- 每行直接 **重启**、**启动**、**停止**，操作后列表自动刷新。
- 状态用颜色和图标区分：运行中、失败、已停止一眼可辨。

## 界面速览

| 区域     | 位置           | 说明                                                                             |
| -------- | -------------- | -------------------------------------------------------------------------------- |
| 标题行   | 页面最上方     | 「Systemd 服务」标题 + 副标题「用户服务 (systemctl --user)」；右侧 **刷新** 按钮 |
| 搜索框   | 标题行下方左侧 | 按服务名 / 描述搜索（不区分大小写，多关键词为「并且」）                          |
| 显示全部 | 搜索框右侧     | 复选框「显示全部 (含未激活)」；默认只列出 active 的服务                          |
| 服务列表 | 主体           | 一张卡片内逐行排列，每行左侧图标 + 名称，右侧操作按钮                            |

每一行从左到右：状态图标、等宽字体的**服务名**（`xxx.service`）、一枚状态 chip 显示
`active / 子状态`，下方小字是**描述**；最右侧是三个位置的图标按钮（悬停显示名称）：

- **重启**（mdi-restart 圆形箭头）：只有服务正在运行时可以点。
- **启动** 或 **停止** 二选一：服务 active 时显示红色 **停止**（mdi-stop），否则显示绿色
  **启动**（mdi-play）。

图标按钮都没有文字，鼠标悬停一秒会浮出名称；操作执行期间对应按钮会转圈。

## 状态怎么看

chip 里是两个用 `/` 分开的值：`active` 状态和 `sub` 子状态，颜色与图标随之变化：

| active 状态           | 图标与颜色   | 含义                                 |
| --------------------- | ------------ | ------------------------------------ |
| `active`              | 绿色播放图标 | 正在运行（子状态多为 running）       |
| `failed`              | 红色警告图标 | 启动失败或运行中出错                 |
| 其它（如 `inactive`） | 灰色停止图标 | 没在运行（子状态多为 dead / exited） |

常见的子状态：`running`（进程在跑）、`exited`（跑完正常退出，很多一次性服务停在这里）、
`dead`（已停止）、`failed`（失败）。状态只是展示 systemctl 的原始输出，不额外加工。

## 常见操作

### 启动 / 停止 / 重启一个服务

1. 在列表里找到目标行（用搜索框过滤更快）。
2. 点该行右侧对应图标按钮：运行中点红色 **停止**，停着时点绿色 **启动**，
   任何 active 的服务都能点 **重启**。
3. 按钮转圈几秒后列表自动刷新，chip 换成新状态。

如果操作失败（例如 unit 不存在、被系统策略拦截），列表不会更新，错误会记入日志——
可以切到「日志」能力里搜 `systemd` 查看具体原因。

### 只看运行中的服务

默认就是「只看 active」。想看全部（包括 inactive / failed），勾上搜索框右边的
**显示全部 (含未激活)**；取消勾选即回到精简视图。搜索与这个勾选可以叠加。

### 找不到某个服务？

这个页面列的是**用户级**服务（`systemctl --user`）。系统级服务（`systemctl` 不带 `--user`）
不在这里——除非 Cockpit 本身是以 root 运行的，那时才会去列系统服务。想看某个服务属于哪一类，
可以在终端里执行 `systemctl --user list-units --type=service --all` 对照。

## 命令行

```bash
systemd.list                                        # 列出用户 systemd 服务
systemd.action --name myservice --action restart    # 启动/停止/重启（action = start | stop | restart）
```

## 常见问题

**列表是空的？** 当前过滤条件下没有服务：默认只看 active，一台刚开机的机器可能真的没有活跃的
用户服务——勾上 **显示全部 (含未激活)** 再看。搜索词也会过滤，清空搜索框试试。

**操作没反应 / 状态没变？** systemctl 执行失败时列表保持原样，错误进日志（「日志」能力里搜
`systemd`）。用户服务一般不需要密码；如果 unit 本身需要额外权限（例如要动系统资源），失败原因
会在日志里写明。

**页面数据是实时的吗？** 进入页面时读取一次，每次操作后刷新一次；不会自动轮询。
想看最新状态点右上角 **刷新**。

**切到别的能力再回来会怎样？** 这个页面不缓存，每次进来都会重新读取服务列表。
