# 脚本工作流

> 最后更新：2026-10-01

脚本工作流（Workflow Scripting）是一个内嵌的 TS / JS 运行时：在页面里写脚本，直接调用 Cockpit 的
所有命令（`cockpit.command`）、执行 Shell、读写文件、发通知，并把执行过程打印在页面下方的控制台。
脚本保存在 `~/.config/LinuxCockpit/scripts/`，可随时重新打开。

> 一句话上手：从顶部 **模板** 菜单选一个预设（如「系统健康巡检报告」）→ 右侧 **参数配置** 面板
> 填参数 → 点右上角 **运行**（或按 Ctrl+Enter）→ 在下方控制台看输出。

## 能做什么

- 用 TypeScript / JavaScript 写自动化脚本，`await` 直接调 Cockpit 命令（仪表盘、镜像源、容器、systemd…）。
- 声明 `export const config = { … }` 就能在右侧自动生成参数表单，不用手写输入框。
- 执行 Shell（`cockpit.sh` / `cockpit.exec`）、读写本地文件（`cockpit.fs`）、发起网络请求（`cockpit.fetch`）。
- 发送系统通知（`cockpit.notify`）、用 KV 存储跨次运行保留状态（`cockpit.storage`）。
- 控制台实时显示日志、stdout/stderr、进度条、耗时与脚本 `return` 的返回值。
- 长任务可以在脚本里转交后台作业（`cockpit.job('script-run', …)`），跨页面继续跑。

## 界面速览

| 区域         | 位置               | 说明                                            |
| ------------ | ------------------ | ----------------------------------------------- |
| 顶部工具栏   | 页面最上一行       | 文件与编辑操作、运行 / 停止                     |
| 编辑区       | 工具栏下方偏左     | 行号槽 + 代码编辑框，顶部一条显示文件路径与行数 |
| 分隔条       | 编辑区与控制台之间 | 按住上下拖动可调整控制台高度                    |
| 控制台       | 页面下半部分       | 状态、耗时、行数、输出流、返回值                |
| 参数配置面板 | 页面右侧（可收起） | 按脚本里的 config 声明生成表单                  |

**顶部工具栏从左到右**：

- 文件名胶囊：`脚本名.语言`，有未保存修改时后面跟一个 `•`。
- **TS / JS** 切换按钮（决定保存扩展名与编译方式）。
- 图标按钮（悬停显示名称）：**新建**、**打开**、**从磁盘重新加载**（仅当脚本有路径时出现）、
  **保存**、**查找**。
- 文字按钮：**模板**（内置预设）、**已存脚本 (n)**（有保存记录时才出现）、**代码片段**（插入常用代码）、
  **参数配置**（开关右侧面板，徽标显示参数个数）。
- 最右侧：**运行**（按钮上标注 `Ctrl+↵`）；运行中变为 **停止**。

## 常见操作

### 用内置模板起步

点 **模板**，菜单里列出全部预设，每条带一行说明：

| 模板                  | 用途                                                    |
| --------------------- | ------------------------------------------------------- |
| Cockpit IPC 快速上手  | 演示声明参数、调用命令、执行 Shell 与上报进度的最小样例 |
| 系统健康巡检报告      | 汇总系统统计、GPU 负载、Docker 容器与 systemd 服务状态  |
| Arch 镜像源测速与分析 | 通过 `mirror.get` / `mirror.test` 测速并列出最优镜像源  |
| 壁纸随机轮换工作流    | 扫描壁纸目录并随机应用一张，可切换后发通知              |
| 数据管道与本地归档    | 抓取日志、统计等级分布、写本地 JSON 归档并发通知        |

点某一条即整份载入编辑器，参数表单随之生成。

### 新建、保存与打开

- **新建**：得到一份带注释的 `untitled.ts`。
- **保存**（或 Ctrl+S）：已有路径直接写盘；新脚本会弹「另存为」对话框选位置。
- **打开**：文件选择框（`*.ts` / `*.js` / `*.mjs` / `*.cjs`），读入编辑器。
- **从磁盘重新加载**：放弃编辑器里的改动，重新读取磁盘版本。
- **已存脚本 (n)**：列出 `~/.config/LinuxCockpit/scripts/` 下的脚本（按修改时间倒序），
  点标题载入，行尾垃圾桶图标删除（删掉当前正在编辑的那个会顺带新建空脚本）。

下次进入页面会自动恢复上次打开的那个文件。

### 填参数

在代码里写：

```ts
export const config = {
  wallpaperDir: { type: 'path', label: '壁纸目录', default: '~/Pictures' },
  checkGpu: { type: 'boolean', label: '检查 GPU 状态', default: true },
  concurrency: { type: 'slider', label: '任务并发数', min: 1, max: 10, default: 3 }
}
```

右侧 **参数配置** 面板会即时生成控件（停止输入约 0.25 秒后解析）：字符串 → 输入框、
开关 → 开关、下拉 → 下拉（取 `options` 的 label/value）、滑块 → 滑杆、`secret` → 密码框
（眼睛图标切换可见）、`path` → 输入框加文件夹按钮（弹出选择框）、数字 → 数字输入框。
面板顶部 **重置默认值** 图标可一键回到 `default`；没有声明参数时空面板会给出
**插入参数声明** 按钮。脚本里通过 `cockpit.config.参数名` 读取。

### 运行与停止

1. 点右上角 **运行**，或在编辑器里按 Ctrl+Enter。
2. 控制台状态变成「运行中」，出现进度条；`cockpit.progress(40, '文字')` 会同时更新进度和文案。
3. 运行中点 **停止**：主进程中断脚本，已启动的子进程会被杀掉，状态变「已中止」。
4. 正常结束状态为「执行成功」，抛错为「执行失败」，耗时与日志行数显示在工具栏。
5. 脚本顶层 `return` 的对象显示在控制台底部的「返回值:」框里。

注意：有对应磁盘文件且编辑器没有未保存修改时，运行前会先用磁盘版本覆盖编辑器内容。

### 看输出

- 每行输出带时间戳和类型标签 `[log]` / `[info]` / `[warn]` / `[error]` / `[stdout]` / `[stderr]` /
  `[result]` / `[system]`，不同类型用不同颜色。
- 控制台右上角三个图标（悬停显示名称）：**自动滚动**（开关，开启时始终滚到最新）、
  **复制**（把全部输出复制到剪贴板）、**清空**。
- `cockpit.command(...)` 的返回对象可以用 `cockpit.log(obj)` 打印，会被格式化成缩进 JSON。

### 查找与替换

Ctrl+F（或工具栏 / 编辑区左上角的放大镜）打开右上角浮动搜索框：输入即显示匹配计数，
Enter 跳到下一个、Shift+Enter 上一个，`Aa` 图标切换区分大小写，Esc 关闭。
点搜索框左侧的向下箭头展开替换行：**替换** 替换当前匹配，**全部替换** 一次替换全部。

### 代码片段

**代码片段** 菜单可一键插入：声明参数配置、调度 Cockpit 命令、执行 Shell、读文件、写文件、
网络请求、延时、发送系统通知、持久化 KV 存储。插入位置在光标处。

## 隐私与安全

- `scripting.run` 与 `scripting.eval` 属于「执行任意代码」类命令，AI / 远程调用前需要
  system.exec 授权；界面里由你本人操作不受影响。
- `secret` 类型的参数在界面上是密码框，AI 无法读取；但请把它当作前端输入，脚本里怎么用由你决定。
- 脚本能力等同于本机管理员：能跑任意命令、写任意路径。只运行你看得懂的脚本。

## 命令行

界面是这些命令的封装：

```bash
scripting.run --code "cockpit.log(1+1)" --lang js          # 运行一段 JS/TS
scripting.eval --expr "cockpit.listCommands()"             # 快速求值一个表达式
scripting.stop                                             # 停止正在运行的脚本
scripting.parseConfig --code "export const config = { … }" # 解析参数结构
scripting.list                                             # 列出已保存脚本
scripting.load --path ~/.config/LinuxCockpit/scripts/demo.ts
scripting.save --name demo --code "…" --lang ts --path /abs/demo.ts
scripting.delete --path demo.ts                            # 删除（路径或文件名）
scripting.templates                                        # 内置模板列表
```

## 常见问题

**控制台没有任何输出？** 脚本可能没打日志就结束了：加 `cockpit.log('start')` 确认已进入；
若显示「暂无运行输出」，说明还没运行过。

**提示「执行失败」但看不到原因？** 出错信息以 `[error]` 行打印，通常是 TypeScript 类型问题、
命令名写错或命令所在能力未加载（先 `cockpit.listCommands()` 确认命令存在）。

**参数面板是空的？** 代码里没有 `export const config = { … }`，或写法不完整。
点空面板里的 **插入参数声明** 套个样例再改。

**长任务一换页面就停？** 页面内运行是前台执行。在脚本里用
`await cockpit.job('script-run', { code, language })` 转交后台作业，即可在侧栏后台任务里继续跑。
