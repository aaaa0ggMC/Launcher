# AI 循环（工作原理）

> 最后更新：2026-10-03

这一页讲 AI DJ 的「Agent 选歌」是怎么跑的：从你一句自然语言，到一份排好序、带开场白的歌单，中间经历了什么。
相关设置集中在 **设置 → AI DJ → AI 循环 / AI loop**。

> 一句话上手：**循环模式** 保持默认的 **Agent（工具检索曲库）** 就好——你只管说想要什么，
> 挑歌、排序、写串场词都交给 AI；想看懂过程，看每条回复上方的 workflow 卡片。

## 两种循环模式

| 循环模式                   | 说明                                                                                  |
| -------------------------- | ------------------------------------------------------------------------------------- |
| **Agent（工具检索曲库）**  | 默认。AI 通过工具在**标签层**筛选曲库、调用子 Agent 挑歌，一批歌是一次完整 workflow。 |
| **文本（整库注入提示词）** | 旧方式：把整库列表直接放进提示词，模型一次看完再选。                                  |

- 切换 **循环模式** 只对**新开的会话**生效。
- 「AI 循环」里的其他设置从**下一批**生效，持续会话不用重启。
- 即时聊天（主页输入框）和持续会话在 Agent 模式下走**同一套 workflow**，区别只是生成完要不要接着放下一批。

## 一批 = 一次 workflow

一批（batch）从你的消息开始，到一份排序好的歌单结束，流程固定是
**LoopAgent →（子 Agent）→ RankAgent**：

| Agent          | 干什么                                                                                                                                                 |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **LoopAgent**  | 理解你的请求、调用工具、组织整批流程。它不逐首翻曲库，而是在**标签层**判断（看标签云、按标签批量保留 / 剔除），具体挑歌交给子 Agent 或检索工具。       |
| **LibAgent**   | 读一段曲库（标签 + 评语），按 LoopAgent 给的描述挑歌。范围由 LoopAgent 决定：当前候选池（默认）、整库（"all"）、一组明确的歌（ids），或筛选条件。      |
| **DreamAgent** | 给它起点歌曲（含标签、评语、歌词片段），它联想这些歌打开的「画面」，并在指定范围内往外扩展。                                                           |
| **RankAgent**  | LoopAgent 一结束就由系统**固定执行**（可在设置里关）：拿到全部候选的完整信息，排序、剔除不合适的、写 DJ 开场白。LoopAgent 最后的回复只是交给它的说明。 |

分工原则是「判断交给 LLM，合法性由代码保证」：ID 必须存在；已播的歌不能再加（钉住的起点除外）；
自主续播时每批同歌手上限；子 Agent 只能返回范围内的歌；RankAgent 不能加新歌；钉住的起点一定排第一。

如果 RankAgent 的输出解析失败：保留钉住的起点 + 前 N 首候选（N = 每批歌曲数），卡片上会显示
「未解析到 RankAgent 的顺序，沿用前 N 首候选」；正常时最多保留每批数量的 1.5 倍候选。

候选数 = 每批歌曲数 × 候选倍数（默认 8 × 2 = 16 首候选，最后留下约 8 首）。

RankAgent 会为每首剔除的歌写一句理由。理由**不在界面上显示**，只记在 workflow 卡片里「RankAgent 排序」那一步的
原始结果 JSON（`dropped: [{track, reason}]`）中，供复核；导出 Markdown 选「完整」时也会带上。

## LoopAgent 的工具

| 工具                                               | 作用                                                                                                                             |
| -------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `use_playbook`                                     | 取某个范式（playbook）的完整步骤                                                                                                 |
| `search_titles`                                    | 按歌名 / 歌手检索全部歌曲（简繁互通；已播的会标出）                                                                              |
| `search_lyrics`                                    | 歌词全文检索（简繁、空格、标点都不影响，返回命中的那句原文）。子 Agent 看不到歌词，你引用 / 描述歌词时就靠它                     |
| `get_songs`                                        | 查看歌曲完整信息，`include_lyrics` 可附歌词片段                                                                                  |
| `tag_cloud`                                        | 当前候选池的标签云（情绪 / 风格 / 语言 / 响度及数量）                                                                            |
| `filter_library`                                   | 按标签（或歌词）批量保留 / 剔除，缩小本批候选池；会把池子清空的过滤会被拒绝，`reset` 重来                                        |
| `search_library` / `similar_to` / `recent_history` | 池内检索 / 按标签相似度找共鸣歌曲（默认其他歌手）/ 最近播放                                                                      |
| `random_pick`                                      | 在**当前候选池**内随机抽歌（排除已播与已加入的），可加筛选、限同歌手，默认避开最近播过的歌手；`queue=true` 直接加入候选          |
| `ask_library_agent` / `dream_from_seeds`           | 调用 LibAgent / DreamAgent                                                                                                       |
| `queue_tracks` / `unqueue_tracks`                  | 按 ID 加入 / 移出候选；`pin_first` 把起点钉在本批第一首                                                                          |
| `no_music`                                         | 你这一轮不想听歌（只想聊天、问问题、说停）：这一轮不加歌、不跑 RankAgent，LoopAgent 的回复直接作为回答；持续模式下会暂停自动续播 |
| `web_search`                                       | 联网搜索（Tavily），只在设置里开启且填了 key 时出现                                                                              |

工具结果里每首歌带一个短 ID（形如 `#k3f9`），同一曲库下稳定不变，AI 用 ID 而不是照抄歌名。

## 四个内置范式

范式（playbook）是「这类需求一般怎么做」的步骤建议，不是死流程：LoopAgent 在系统提示里只看到目录
（id + 何时用），需要时用 `use_playbook` 取详细步骤。

| 范式          | 什么时候用                                                       | 大致步骤                                                                                                                                      |
| ------------- | ---------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `seed_start`  | 从一首歌 / 一句歌词 / 一个短语开始（例如「从"辽阔的森林"开始」） | 歌名检索 → 没命中就歌词检索 → 看完整信息含歌词 → 选起点（情绪不相容就只选一首）→ 钉为第一首 → 按标签剔除不合适的 → DreamAgent 扩展 → 交接说明 |
| `artist_pick` | 某个歌手（例如「来点周杰伦」）                                   | 歌名检索拿到该歌手的歌 → 多的话交给 LibAgent 按当前心情挑 → 加入（你点名歌手时不受同歌手上限）                                                |
| `radio_flow`  | 没有新要求时的自主续播                                           | 读最近序列 → 剔除会打断走向的标签 → 用一首最近的歌当锚点让 DreamAgent 往下走；也可以 `random_pick` 一两首加点惊喜                             |
| `chat`        | 只聊天 / 不听歌                                                  | 先 `no_music`，需要事实就 `web_search`，用你的语言直接回答；可以之后再提议放歌                                                                |

## workflow 卡片怎么看

每一批有一张卡片，在聊天里位于 AI 回复上方；持续模式的**后台任务面板**里也有。

- **标题栏**：所用范式、状态（运行中 · 第 n 轮 · 上限 m / RankAgent 排序中 / 结果）、本批 tokens、耗时。
- **结束后自动折叠**成一行摘要，例如「5 轮 · 7 次调用 · 候选 16 → 入选 8 · 剔除 8」；
  只聊天时是「仅对话 · 2 轮 · 4 次调用」。
- **点开时间线**：每一行是「哪个 Agent（LoopAgent / LibAgent / DreamAgent / RankAgent 颜色区分）+ 工具名 +
  一句话摘要」，例如「标签过滤 3223 → 2636 首」「歌词检索 “辽阔的森林” → 2 首」「钉为起点 +1」
  「16 选 8 · 剔除 8」，并带耗时；某一行再点开可以看到原始参数与结果。
- 等待期间，「思考中」气泡显示当前阶段，例如「LoopAgent 思考中 · 第 5 轮」「LoopAgent · 标签过滤…」
  「DreamAgent 扩展…」「RankAgent 排序中…」（文本模式的气泡仍显示字符数）。
- 卡片会保存在会话记录里（**不进入 AI 的记忆**），重新打开会话卡片还在，原始结果每项最多保存 1500 字。

## 只聊天（这一轮不听歌）

- 说「不听歌，我们聊聊…」或问与选歌无关的问题：LoopAgent 会调 `no_music`，这一轮**不出歌单**，直接回答，
  需要事实时可以联网搜索，并会区分已证实与传闻。
- 持续模式下，这一轮之后**自动续播暂停**，聊天里提示「⏸ 这一轮只聊天，自动续播已暂停；发消息即可继续」；
  下一条消息又要听歌则恢复（「▶ 已恢复自动续播」）。
- 卡片摘要会写成「仅对话 · n 轮 · m 次调用」，不会出现歌单。

## 设置项

都在 **设置 → AI DJ → AI 循环 / AI loop**：

| 设置项                                                              | 默认       | 说明                                                                                                                                        |
| ------------------------------------------------------------------- | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 循环模式 / Loop mode                                                | Agent      | **Agent（工具检索曲库）** 或 **文本（整库注入提示词）**，改动对新开的会话生效                                                               |
| 曲库排列 / Library order                                            | 按情绪分组 | 按情绪分组 / 按风格分组 / 字母序（旧）。按情绪分组会让文本模式提示词里的曲库按情绪组合分组、组内打散同歌手，子 Agent 读到的片段也用这个顺序 |
| 每批同歌手上限 / Max tracks per artist per batch                    | 2          | 只限制自主续播；你点名歌手时不限。0 = 不限                                                                                                  |
| 每批歌曲数 / Tracks per batch                                       | 8          | 一批最终入选几首                                                                                                                            |
| 队列少于几首时补货 / Refill when queue below                        | 8          | 队列少于这个数就生成下一批                                                                                                                  |
| 参考最近几首 / Recent tracks as context                             | 15         | 给 AI 看最近播放了几首作参考                                                                                                                |
| Agent 每批最多工具轮数 / Max agent tool rounds per batch            | 14         | 「轮」= 一次 LLM 往返，一轮可以同时调用多个工具；界面显示的上限 = 它 + 1 次强制收尾。上限不是目标，什么时候结束由模型决定                   |
| 允许委派曲库子 Agent / Allow library sub-agent                      | 开         | 由主 Agent 决定曲库范围                                                                                                                     |
| 标签过滤力度 / Tag filter strength                                  | 中         | 轻 / 中 / 强                                                                                                                                |
| 候选倍数 / Candidate factor                                         | 2          | 候选数 = 每批 × 倍数                                                                                                                        |
| RankAgent 排序并写 DJ 词 / RankAgent orders and writes the DJ intro | 开         | 关掉后不跑排序环节，开场白由 LoopAgent 自己写                                                                                               |

## 进阶：提示词与范式文件

- 提示词模板不在代码里：一个模板一个文件放在 `src/abilities/aidj/loop/prompts/*.md`。
  可以在 `~/.config/LinuxCockpit/aidj/config.json` 的 `preferences.loop_prompts.<名字>` 覆盖某个模板。
- 范式同样是一个文件一个：放 `src/abilities/aidj/loop/playbooks/` 下的 `.md`
  （开头 `---` 块写 `id` / `title` / `when`，正文写步骤），或在 `config.json` 的
  `preferences.loop_playbooks`（数组，每项 `{id,title,when,steps}`）里新增；同 id 覆盖内置。
- 想临时禁用某个范式：`preferences.loop.disabled_playbooks`。
- 歌手解析会识别「歌名 - 歌手」这种反向命名（例如 `七里香 - 周杰伦`）。

## 进阶：预览下一批

```bash
aidj.loop-preview --task <持续会话任务 id>            # 不调用 AI，预览下一批会发出的指令、可用工具、范式
aidj.loop-preview --task <持续会话任务 id> --system true   # 连系统提示一起预览
```
