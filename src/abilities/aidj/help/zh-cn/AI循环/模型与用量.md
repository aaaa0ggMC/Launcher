# AI 循环（模型与用量）

> 最后更新：2026-10-03

这一页讲 AI DJ 的模型怎么分配、tokens 怎么算、缓存命中率为什么有时看起来不高，
以及可选的联网搜索和密钥是怎么保存的。

> 一句话上手：不折腾的话只用改 **默认模型**；想省钱或提速，再把某个特别啰嗦的 Agent
> 换成更便宜的模型。token 用量看状态栏 **Tokens**，鼠标悬停能看到缓存命中率。

## 模型细则

入口：AI DJ 页面菜单 → **模型细则 / Models**，或 **设置 → AI DJ → AI 模型 / AI Models**。两种入口是同一个界面。

可配置的行：

| 行                          | 用在哪                                         |
| --------------------------- | ---------------------------------------------- |
| 默认模型 / Default model    | 文本模式、标题生成，以及所有没单独设置的 Agent |
| LoopAgent                   | 组织整批 workflow 的主 Agent                   |
| LibAgent                    | 曲库子 Agent（读一段曲库按描述挑歌）           |
| DreamAgent                  | 起点联想扩展                                   |
| RankAgent                   | 排序、剔除、写 DJ 开场白                       |
| VocabAgent                  | 标签整理时生成规范词表                         |
| SanitizeAgent               | 标签整理时逐首清洗不符合词表的歌               |
| 元数据模型 / Metadata model | 同步新歌时提取语言 / 情绪 / 风格 / 响度 / 乐评 |

- 每个 Agent 下拉的第一项是 **跟随默认（模型名）**：选它或清除，就跟随默认模型。
- 列表里没有的模型名可以直接手输。
- 修改**即时保存，下一批生效**；所以聊天页和持续模式面板里**不再有模型下拉**。
- 不同 Agent 的分工见 [AI 循环（工作原理）](工作原理.md)。

## Tokens 实时与悬停明细

- 状态栏 **Tokens** 在当前会话已有累计的基础上实时累加：每次 LLM 调用一结束就加，**包括子 Agent**。
- **Context / Completion** = 最近一次 LoopAgent 调用的输入 / 输出。
- **鼠标悬停 Tokens** 看明细：输入、Cached（缓存命中）及命中率、输出、合计，
  以及**按 Agent 分**的输入 / Cached / 输出。
- 缓存字段按接口能力读取：DeepSeek 用 `prompt_cache_hit_tokens`，OpenAI 用
  `prompt_tokens_details.cached_tokens`；接口没返回时会注明。
- 会话记录会保存每一轮的 tokens（含按 Agent 拆分）和 Context；打开会话 / 回退 / 从此处分支 / `/persist`
  都会从记录恢复。**更早版本生成的会话没有这些数据，显示 0。**

## 缓存命中率怎么看

整体命中率明显低于 LoopAgent 的单项命中率，通常是正常的，原因在各 Agent 的输入内容不同：

| Agent                 | 缓存情况                                                                                                                                                                          |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| LoopAgent             | 每轮都会重发前面的对话，前缀相同，命中率应该很高（实测约 80%）。                                                                                                                  |
| LibAgent / DreamAgent | 输入主要是曲库片段。同一个候选池或整库在同一批、跨批调用时片段保持不变，可以命中缓存；但**每次新过滤出的候选池第一次被读取时是未命中的**，这部分 token 量大，会把整体命中率拉低。 |
| RankAgent             | 主要输入是这一批独有的候选列表，每批都不一样，命中率低是正常的，总量也小。                                                                                                        |

结论：看整体命中率只有百分之二三十不必紧张，重点看 **LoopAgent 的单项命中率**——那才代表
「上下文被反复复用」是否生效。之前版本子 Agent 的片段会随加歌变化导致几乎 0 命中，已修复
（排除列表改放在提示末尾）。

另外，DeepSeek 的缓存按前缀匹配、是尽力而为的：**刚发出的请求需要一点时间才会被缓存**，
并行发出的请求彼此也用不上缓存。

## 联网搜索（Tavily）

设置入口：**设置 → AI DJ → 联网搜索（Tavily） / Web search (Tavily)**。

| 设置                                    | 说明                                                                               |
| --------------------------------------- | ---------------------------------------------------------------------------------- |
| **允许 AI 联网搜索 / Allow web search** | 开关。打开**且**填了 Key，`web_search` 工具才对 AI 可用；没填 Key 时设置页会提示。 |
| **Tavily API Key**                      | 凭据，只写不回显，加密保存。                                                       |
| **结果数 / Results**                    | 每次搜索取回几条结果，默认 5，最多 10。                                            |
| **搜索深度 / Depth**                    | 基础 / 深入。                                                                      |

- 用途：查歌手、歌曲、作品、新闻等**事实**，帮 AI 理解你的请求；**歌曲仍然只从你的曲库里选**。
- 网页内容被当作不可信资料，AI 不会执行其中的指令。
- 请求走系统代理。
- **AI 生成的搜索词会发送到 Tavily**，不开这个开关就不会有任何搜索请求。

## 密钥是加密保存的

- **API 密钥**和 **Tavily Key** 都加密后才写进 `~/.config/LinuxCockpit/aidj/config.json`
  （`enc:v2:` 前缀，使用 Cockpit 的加密模块），只在内存里解密。
- 旧的明文 Key 在第一次读取时自动迁移成密文。
- 设置页**只写不回显**：保存后显示「已设置（加密保存，不回显）— 输入新值即替换」，
  旁边有 **清除已保存的密钥** 按钮。AI 读不到，也无法通过命令改写。
- 迁移成密文后**不要回退到更早的版本**——旧版会把密文当成 Key 来用。
