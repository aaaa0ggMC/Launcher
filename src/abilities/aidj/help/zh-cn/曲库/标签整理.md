# 标签整理

> 最后更新：2026-10-03

标签整理用来把元数据里同质化的标签合并成一份干净的**规范词表**，再把不符合词表的歌曲清洗一遍：
比如情绪里同时有「治愈」「治愈系」「放松」，可以决定统一成「治愈」。
整理结果写进**新的元数据槽位**，原始数据不动，随时可以一键切换或切回。

入口：AI DJ 页面菜单 → **标签整理 / Tag cleanup**（整页视图）。

> 一句话上手：勾选要整理的字段 → 写几句额外要求 → 点 **生成规范词表** → 在
> **审核**页过一遍映射（可手改）→ 点 **预估** 看看有多少首要处理 → 点 **开始整理（后台）**
> → 完成后到 **整理记录** 点 **使用整理后的元数据**。

## 整理流程

四个步骤在页面里依次排开，可以随时离开页面：两个耗时节点都是**后台任务**，回来页面接着显示进度。

### 1. 要求

- 勾选要整理的字段：**情绪** / **风格** / **语言** / **响度**（旁边显示当前有多少种标签）。
- 写**额外要求**（默认英文，例：「使用中文；情绪控制在 30 个以内；保留 city pop」）。
- 点 **生成规范词表 / Generate vocabulary**。

细节：

- 每个字段由 VocabAgent 调用一次；某个字段标签超过 120 个时分两步：先生成规范标签，再把旧标签
  每 120 个一组并行生成映射。
- 作为后台任务运行，可以离开页面；回来能看到每个字段的进度（等待模型响应 / 思考中 / 输出中 · 已生成 N 字 / 完成），
  也可以随时停止，后台面板里有日志。
- **历史草稿 / Earlier drafts**：每次新提案替换草稿前，旧草稿会存档（最近 10 份），可以恢复
  （恢复时当前草稿会先存档）。

### 2. 审核

每个字段一页，从上到下：

- **摘要**：例如「343 个标签 → 52 个规范标签 · 删除 n · 全部按映射直接清理」，
  或「… n 个未映射（相关歌曲交给 SanitizeAgent）」。
- **规范标签**：最终保留的词表，可以删，也可以新增。
- **映射列表**：每条旧标签 → 目标规范标签，可搜索、可只看有变动的、可逐条编辑——
  换成另一个规范标签，或**留空 = 删除该旧标签**。
- **对这个字段的意见** + **按意见重做此字段**：不满意就写意见重做这一字段，不用全部重来。

在这里的修改会自动保存。执行时**每一首歌**的所选字段都按映射改写成规范标签，不在词表里的标签不会保留；
只有带「未映射」旧标签的歌才会交给 SanitizeAgent。

### 3. 执行

两项设置：

- **尝试补全未知语言（信息不足时仍保留 unknown）**：默认开。
- **SanitizeAgent 每次处理几首**：默认 1，最多 20。

先点 **预估 / Estimate**：显示每个来源有多少首**直接映射**、多少首**需要 SanitizeAgent**、
主要原因，以及多少首可以**复用缓存**。心里有数后点 **开始整理（后台）**。

- SanitizeAgent 每首的输入是原始元数据 + 歌词片段，输出只能用词表里的标签
  （代码校验，不合规重试一次，仍不合规的标签丢弃）。
- 语言信息不足时保持 `unknown`，不猜。
- 每首结果按**词表版本**缓存：中途停止后，用同一份词表重新开始会接着做。

### 4. 结果写入新槽位（copy + forward）

整理结果不会覆盖原数据：

- 主曲库写入 `Sanitized-<日期>.metadata`，B 站槽位写入 `Bilibili-Sanitized-<日期>.metadata`；
  新槽位先登记为**禁用**再写，原数据不动。
- 某个来源整理前后**完全没变化**时不新建槽位，记录里显示「n 首均无变化，沿用原槽位」。

## 整理记录：切换与切回

页面里的 **整理记录 / Cleanup runs** 列出一路上的整理：

- **使用整理后的元数据 / Use cleaned metadata**：启用新槽位、禁用来源槽位、把普通同步与
  B 站导入的写入目标改到新槽位、并启用这份词表。
- **切回之前的元数据 / Switch back**：恢复原状；如果是「在上一次整理结果的基础上又整理的」，
  切回的是上一次。

两个注意点：

- **Forward**：正在使用整理后的元数据时，之后同步的新歌（含 B 站导入）写入时会**按词表规整**，
  元数据提取提示词也会带上允许的标签；词表里没有、映射里也没有的标签会被丢弃，语言变成 `unknown`。
- 因为**来源 = 当前的写入目标**，所以可以在一份整理结果上再整理一次。
- 切回原数据后，在整理后槽位里新同步的歌在原槽位没有记录，下次同步会被当作新歌重新提取。

## 语言 unknown 的规则

Agent 选歌时按语言过滤**永远不会剔除**语言未知的歌——标签缺失不等于语言不符；
子 Agent / RankAgent 也被告知不要因为 `unknown` 剔歌。整理时同理：信息不足就保留 `unknown`，宁缺勿猜。

## 文件位置与命令

数据放在 `~/.config/LinuxCockpit/aidj/sanitize/` 下：

| 文件            | 内容                   |
| --------------- | ---------------------- |
| `draft.json`    | 当前草稿               |
| `drafts/`       | 历史草稿               |
| `runs.json`     | 整理记录               |
| `active.json`   | 使用中的词表           |
| `cache-*.jsonl` | 断点缓存（按词表版本） |

命令行：

```bash
aidj.tags-cloud                               # 标签云（整理前先看分布）
aidj.vocab-draft                              # 查看规范词表草稿（--set <json> 保存修改）
aidj.vocab-drafts                             # 历史草稿列表
aidj.vocab-draft-restore --version <n>        # 恢复某份历史草稿
aidj.sanitize-estimate                        # 整理预估
aidj.sanitize-runs                            # 整理记录
aidj.sanitize-switch --run <id> --use sanitized   # 使用整理后的元数据（--use original 切回）
```

两个耗时节点是后台作业，用 `background.job --name aidj.vocab-propose`（生成词表）和
`background.job --name aidj.sanitize`（执行整理）触发；界面入口就是本页的四个步骤。
