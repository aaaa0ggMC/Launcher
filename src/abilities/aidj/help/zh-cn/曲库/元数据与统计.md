# 曲库与元数据

> 最后更新：2026-10-06

这一页讲 AI DJ 的「后台」：曲库怎么扫、元数据（语言 / 情绪 / 风格 / 响度 / 乐评）怎么来、
播放频率和听歌时长存在哪、B 站视频怎么变成曲库里的歌。所有数据都在本机
`~/.config/LinuxCockpit/aidj/` 目录下。

> 一句话上手：AI DJ 页面菜单 → **更新 MetaData**，它会扫描曲库里缺元数据的新歌并补全；
> 想只让一部分元数据生效，用 **元数据槽位** 勾选。

## 数据都放在哪

| 路径（相对 `~/.config/LinuxCockpit/`）  | 内容                                                |
| --------------------------------------- | --------------------------------------------------- |
| `aidj/config.json`                      | AI DJ 主配置（API、曲库目录、播放偏好、人设等）     |
| `aidj/music_metadata.jsonl`             | 曲库元数据（默认写入目标）                          |
| `aidj/music_lyrics.jsonl`               | 抓到的 LRC 歌词                                     |
| `aidj/metadata/<名称>.metadata`         | 元数据槽位文件（新建槽位时创建）                    |
| `aidj/frequency.csv`                    | 每首歌的播放次数                                    |
| `aidj/time.csv`                         | 每小时听歌分钟数（听歌时长统计）                    |
| `aidj/songs_timeline.csv`               | 每次听歌事件的时间线                                |
| `aidj/playlists/<名称>.txt`             | 保存的歌单（`aidj.save`）                           |
| `aidj/eq.jsonl`                         | EQ 预设曲线（内置预设也可被改，自定义预设只在这里） |
| `aidj/sessions/main.json` + `sessions/` | 会话索引与会话历史                                  |
| `aidj-lyrics/config.json`               | 歌词页显示配置（与主配置分开）                      |

曲库本身在你自己指定的**音乐目录**里，AI DJ 只读索引和元数据，不移动、不改名你的音频文件
（B 站下载的视频落在音乐目录下的 `Bilibili/<BV号>/` 子目录）。

## 曲库扫描

**设置 → AI DJ → 音乐库与播放器 → 搜索目录**：

- **音乐目录**：递归扫描目录下所有音频文件；可以配多个，按列表顺序用 **上移 / 下移** 调整优先级，
  红色 **×** 删除该目录。填路径或点输入框里的文件夹图标 **选择目录** 都能加，最后点 **添加**。
- **歌词搜索目录**：递归扫描 `.lrc` 文件，供桌面歌词窗口使用（与歌词页共用）。

第一次对话时 AI DJ 会扫描目录并载入元数据，曲库很大时顶栏 **Tracks** 芯片会先显示 `…`。
换曲库后如果数量没刷新，执行 `aidj.reload` 或在 CLI 里跑 `aidj.invalidate-library` 强制重扫。

## 元数据同步（更新 MetaData）

AI DJ 页面菜单 → **更新 MetaData** 会启动「AIDJ 元数据同步」后台任务：

1. 重新扫描音乐目录，只补**新增**的歌（已同步过的不会重复抓）。
2. 对每首新歌去网易云检索，拿到歌词（LRC / 逐字 YRC）与热门评论。
3. 交给 **元数据提取模型** 提取五个字段：`language` 语言、`emotion` 情绪、`genre` 风格、
   `loudness` 响度、`review` 乐评，写入当前写入槽位。
4. 完成后在页面弹提示「元数据同步完成：N」或「没有写入新的元数据」，后台面板里能看到逐首进度。

### 实测响度

同步时还会用 `ffprobe` 实测每首新歌的响度，随元数据一起写入两个可选字段：`loudness_lufs`
（EBU R128 整体响度，LUFS）与 `loudness_peak_db`（真峰值，dBFS）。它们是长期参考：提取模型判断
`loudness`（soft / medium / loud）时以实测值为准，AI 选歌时也能看到这两个数。没装 ffmpeg 或测不出来时
字段留空，其余流程照常。

老歌（升级前就同步过的）没有这两个字段，可在 CLI 里补录：

```
background.job --name aidj.loudness-backfill --args {}
```

它只补缺字段（`{"force":true}` 则全部重测）、同时测 2 首、可在后台面板停止，结果并入当前写入槽位。

第一次打开会话时不会再干等新歌元数据同步——同步改到后台进行，新歌的标签随后自动补齐；歌名末尾含特殊空白字符的歌也不会再每次启动被重复同步。

相关设置都在 **设置 → AI DJ**：

- **NCM API 地址** + **歌词来源**：默认走外部服务
  （[NeteaseCloudMusicApi](https://github.com/Binaryify/NeteaseCloudMusicApi)，默认 `http://localhost:3000`）；
  选 **内置（进程内直连网易）** 前必须先 **签署免责并启用**。
- **同步并发数**（1–16）：同时处理几首歌，越大越快但越吃 API 限额。
- **乐评抓取数量**（0–50）：每首歌抓几条网易热评给 AI 写乐评参考，0 = 关闭。
- **元数据字段注入**：控制哪些字段喂给选歌的 AI（风格 / 情绪 / 语言 / 响度 / 乐评，默认全开）。
- **响度调整 → 调整方法**：LUFS 或 RMS (Linear)，配合**音量曲线**决定动态音量平衡的强度。

歌词来源不可达、或网易云搜不到这首歌时，这首歌**不会写入任何元数据**，下次同步会再试；
后台面板里会区分「未找到歌词 / 网络错误 / 提取失败」三种结果，进度条走到最后
「元数据同步完成：N」里的 N 就是成功提取的曲目数。

## 元数据槽位

元数据默认写进 `music_metadata.jsonl`。**元数据槽位**让你把元数据拆成多个集合，
按需组合生效——例如「只让动画 OST 的元数据参与选歌」，或「B 站下载的歌单独一份」。

AI DJ 页面菜单 → **元数据槽位**：

- 列表头部显示 **生效: N 首**（实时重算）和 **新建合集** 按钮。
- 每个槽位一行：左边三态复选框（全选 / 部分 / 未选）点击即在「整份生效 / 整份不生效」间切换；
  **设为写入** 指定以后同步写入哪份；**设为B站默认** 指定 B 站下载写入哪份；
  右侧箭头 **查看条目** 进入详情；非默认槽位还有红色 **删除槽位**。
  删除是安全的：本地文件会被重命名为 `.deleted` 备份，不会立刻擦除。
- 详情页可以按歌名 / 流派 / 情绪 / 乐评 **搜索**，**全选** / **全不选**，再逐首点行切换生效。

槽位文件放在 `~/.config/LinuxCockpit/aidj/metadata/` 下，新建时在弹窗里起个名字即可
（例如 `AnimeOST`、`JPop-2024`）。

> **标签太乱想先收拾一遍？** 用页面菜单的 **标签整理**：把同质化的情绪 / 风格 / 语言 / 响度标签
> 合并成规范词表并清洗歌曲，结果写进新的槽位（`Sanitized-<日期>.metadata`），原数据不动。
> 使用整理后的元数据后，同步的新歌也会按词表规整；语言信息不足的保留 `unknown`，宁缺勿猜。
> 详见 [标签整理](标签整理.md)。

## 播放频率与听歌统计

- **歌曲频率**（AI DJ 页面菜单）：列出曲库每首歌的播放次数，点封面直接发送到播放器，
  顶部图标切换升 / 降序。开关在 **设置 → AI DJ → 播放偏好 → 记录播放频率**，也可以在对话区状态栏点
  **RecordFreq** 芯片即时切换。
- **听歌时长统计**（AI DJ 页面菜单）：按小时记录听歌分钟数，用热度图展示——
  粒度可选 **日（每天 24h 分布）** / **月（天分布）** / **年（月分布）**，
  输入 `YYYY-MM` 点 **跳转** 看历史，**回到当前** 回到这个月；鼠标悬停格子看该格时长和覆盖率。
  计时在后台跑：每 30 秒采样一次，播放中记 0.5 分钟，**不打开 AI DJ 页面也会记**。
  开关在 **设置 → AI DJ → 播放偏好 → 听歌时长统计**（也可点状态栏 **Listen** 芯片）。
- **记录听歌时间线**：把每次听歌事件追加进 `songs_timeline.csv`，默认开。

统计数据是**个人隐私区**，AI 快照与截图会脱敏。

## Bilibili 视频下载

把 B 站视频（音频）拉进曲库，并让 AI 生成元数据：

1. **设置 → AI DJ → Bilibili 视频导入与扩展**：打开 **已启用 / 已禁用** 开关，
   首次使用会弹免责声明，点 **同意并启用**；然后 **扫码登录** 或 **导入凭据**
   （文件路径、Cookie 字符串或 JSON 均可）。未登录时只能解析 360P/480P 基础画质。
2. AI DJ 页面菜单 → **Bilibili 视频下载**：粘贴 BV / AV 号或视频链接，点 **解析视频**。
3. 多 P 视频会自动拆成多条，标出 **已下载**；可删掉误加的条目或 **清空全部**。
4. 选 **元数据写入槽位**、是否 **跳过已下载**、**仅音频 (m4a)** 还是 **视频流 (mp4)**，
   点 **确认下载 (N 项)** 起后台任务，进度在后台任务面板看。

下载的文件落在音乐目录下的 `Bilibili/<BV号>/`，元数据写进上一步选的槽位
（默认 `Bilibili-Current.metadata`）。播放 mp4 时可以去**歌词**页看 MV，或在设置里打开
**仅音频模式** 只听声音。

## 命令行

```bash
aidj.freq                                   # 播放频率列表
aidj.time-stats                             # 听歌时长（每小时一行）
aidj.time-range --start 1735689600000 --end 1738368000000   # 区间查询（毫秒时间戳）
aidj.sync                                   # 立即同步新歌元数据（前台跑）
aidj.metadata-sync                          # 同上，但走后台任务
aidj.analyse --field genre                  # 某个字段的分布统计
aidj.metadata-slots-list                    # 列出槽位与激活状态
aidj.metadata-slots-toggle --slot AnimeOST  # 整份槽位生效 / 不生效
aidj.metadata-slots-set-write --slot AnimeOST   # 设置写入目标槽位
aidj.bili-resolve --input "BV1xx411c7mD"    # 解析 BV/AV 号，展开分P信息
aidj.save --name 我的歌单 --songs "..."      # 保存歌单
aidj.load --name 我的歌单                    # 读回歌单
aidj.reload                                 # 重新扫描曲库与配置
```

## 常见问题

**新下的歌不在曲库里？** 确认音乐目录配好了、文件确实是音频格式；同步任务跑完后执行
`aidj.reload`，或在页面菜单里重新打开 **歌曲频率** 看数量。

**同步一直卡着 / 大量「未找到歌词」？** 检查外部 NCM 服务是否在跑（`http://localhost:3000`），
或改用内置直连（需签署免责声明）；**同步并发数** 调低一点更稳。

**元数据改了但 AI 选歌没变化？** 看槽位是否生效（列表头部「生效: N 首」），
以及 **元数据字段注入** 里对应字段是否打开。

**统计对不上我实际听的时间？** 计时每 30 秒采样一次、播放中记 0.5 分钟（落盘时四舍五入到整分钟），
暂停不计；程序被强制杀掉时最多丢掉当前未满一小时的那一段。
